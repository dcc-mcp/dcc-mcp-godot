# AGENTS.md — dcc-mcp-godot

> Godot 4 editor adapter for the DCC Model Context Protocol: a GDScript
> `EditorPlugin` plus an `EngineDebugger` runtime peer, exposing on-demand
> capability tools and a tested 2D arena-roguelike skill.
> Navigation map for AI agents, not a reference manual. Follow the links; do not
> read everything up front.

## Build & test

There is no `justfile` or `vx.toml` in this repo — use the commands CI runs:

```bash
python -m pip install -e ".[dev]"   # editable install with dev extras
python -m pytest                    # run the test suite
ruff check src tests tools          # lint
ruff format --check src tests tools # format check (line-length 100, py39 target)
python tools/lint_skills.py         # validate SKILL.md / tools.yaml
python -m build --no-isolation      # build wheel + sdist
```

Live host smoke (what the `godot-latest` CI job does):

```bash
GODOT=$(python tools/download_latest_godot.py --output .godot-bin)
python tests/live_godot_smoke.py --godot "$GODOT"
```

Windowed scene-preview lane (same job, after the smoke). `live_godot_smoke.py`
starts every editor with `--headless`, and the host refuses `render_scene_preview`
under that display driver by design, so the smoke is not coverage of the render
path. This lane starts a windowed editor on Xvfb and calls it for real:

```bash
GODOT=$(python tools/download_latest_godot.py --output .godot-bin)
xvfb-run -a -s "-screen 0 1920x1080x24 -ac +extension GLX +render -noreset" \
  python tests/probe_windowed_preview.py --godot "$GODOT" --out preview-probe --tier B
```

Exit codes are the gate: `0` measured and passed, `1` measured and failed the
criteria, `2` not measured. `2` skips the assertions instead of faking a green
light or blocking every pull request, and the reason is written to
`preview-probe/summary.md` and the job summary. The artifact also carries the
noise floor the run measured, which is the evidence needed before tier B can be
tightened on that platform — never copy another platform's tolerance.

## Agent control path

AI agents drive Godot through the shared gateway using the `dcc-mcp` skill and
`dcc-mcp-cli` REST commands:

```bash
dcc-mcp-cli list                                      # live sessions
dcc-mcp-cli dcc-types                                 # release-catalog support
dcc-mcp-cli search --query "<task>" --dcc-type godot
dcc-mcp-cli describe <tool-slug>
dcc-mcp-cli call <tool-slug> --json '{"key":"value"}'
```

If a tool belongs to an inactive progressive skill, load it first:
`dcc-mcp-cli load-skill <skill-name> --dcc-type godot`.

If `dcc-mcp-cli` is missing, obtain user consent before running the official
install commands in the README Agent workflow. Keep an official build current
with `dcc-mcp-cli update check` / `dcc-mcp-cli update apply` — `update apply`
stages the CLI for the next launch and does not update a running
`dcc-mcp-server`.

## Ports and entry points

| Endpoint | Default | Override |
|---|---|---|
| Stable gateway | `http://127.0.0.1:9765/mcp` | — |
| Adapter MCP port | OS-assigned, registered for CLI discovery | `DCC_MCP_GODOT_PORT` |
| Loopback bridge | `ws://127.0.0.1:3847` | adapter: `DCC_MCP_GODOT_BRIDGE_PORT` (set before starting both processes); addon: `DCC_MCP_GODOT_BRIDGE_URL` (falls back to `ws://127.0.0.1:3847`) |

Start the adapter with `dcc-mcp-godot` or `dcc-mcp-godot serve`.

## Install

The canonical agent-first, three-platform lifecycle is `install.md`:

```bash
dcc-mcp-godot install /path/to/project --dcc-path /path/to/godot --dry-run --json
dcc-mcp-godot install /path/to/project --dcc-path /path/to/godot --yes --json
```

It is plan-first: JSON output, staged project updates, receipts, repair, live
verification, upgrade, and receipt-owned uninstall. The legacy alias
`dcc-mcp-godot-install <project>` still works but only installs — when using it,
enable **DCC-MCP Godot** under **Project Settings > Plugins** manually.

## Release

- release-please drives versioning from Conventional Commits on `main`.
- Whether a release is cut at all is a changelog question, not a prefix question: if every
  commit in the batch lands in a `hidden: true` section the changelog entry is empty, and
  release-please skips the whole batch — no release pull request, **no version bump**
  (`strategies/base.ts` logs “No user facing commits found since … - skipping” when
  `changelogEmpty()` finds only the heading line).
- For `release-type: python`: `chore:`/`ci:`/`style:`/`refactor:`/`test:`/`build:` are
  `hidden: true`; `docs:` is a **visible** `Documentation` section.
- Only once a release *is* cut does the prefix choose the bump: breaking → major,
  `feat:` → minor, anything else → patch
  (`DefaultVersioningStrategy.determineReleaseType()`).
- Use `chore:` when the batch should **not** cut a release; use `docs:` when doc-only work
  should cut a patch release.
- The version is mirrored into `pyproject.toml` and
  `src/dcc_mcp_godot/__version__.py`; do not edit those by hand.

## Do / Don't

- **Do** single-source agent instructions here — this is the only agent contract
  file at the repo root. Rebase onto `main` before merging (no merge commits);
  CI must pass before review.
- **Do** regenerate skills through `tools/generate_capability_skills.py` rather
  than hand-editing `src/dcc_mcp_godot/skills/`, and keep the wheel artifacts
  (`skills/**`, `godot_addon/**`) shipping.
- **Do** treat generated build-optimization disable flags as hypotheses until a
  packaged build is launched and smoke-tested.
- **Don't** add `CLAUDE.md` / `GEMINI.md` / `CURSOR.md` / `ANTHROPIC.md` /
  `OPENAI.md` / `COPILOT.md` / `CODEBUDDY.md` / `.cursorrules` / `.clinerules` /
  `.windsurfrules` at the root. This repo has no `docs/integrations/`; keep any
  vendor-specific notes here.
- **Don't** hardcode an exact version in tests (`assert __version__ == "X.Y.Z"`)
  — release-please bumps will break it. Use `>=` or read package metadata.
- **Don't** commit build artifacts to the repo root (`dist/`, `build/`,
  `coverage.json`, `*.egg-info`, `.godot-bin/`).
- **Don't** add AI-attribution footers to PR bodies or commit messages.
